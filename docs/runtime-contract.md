# Runtime adapter contract v1

`Runtime` / `RuntimeRequest` in `src/types.ts` are the inference boundary. They use application-owned types, strings, JSON tool schemas, image bytes and abort signals, not Pi types. `TaskExecutor` invokes adapters through `runRuntime` in `src/runtime/contract.ts`. The host owns permissions, disclosure, routing, budgets, original evidence, checkpoints, validation and success state. Adapters are trusted in-process implementations, not sandboxed plugins: the guard detects contract violations but cannot stop malicious adapter code from making its own network or filesystem calls.

## Adapter responsibilities

| Surface    | Required behavior                                                                                                                                                                                                                                                                                                                                                            |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Descriptor | Declare version `1`, context `messages-v1`, image/tool capabilities, and a stable versioned native session format if sessions are persisted. Unsupported capabilities fail before invocation; never silently remove tools/images or switch model.                                                                                                                            |
| Model      | `request.model` is an authorized configuration alias. Honor its connection, output/reasoning profile and disclosure policy. Do not discover or select another model, account or endpoint.                                                                                                                                                                                    |
| Context    | Before **every** inference request, call and await `transformContext` with the complete JSON-serializable context. Use its returned context, not the original. Propagate cancellation and transformation failures; do not retry or compact privately.                                                                                                                        |
| Accounting | Reserve through `beforeRequest` before every actual inference dispatch, including tool-loop continuations. Pass bounded text bytes and explicit image counts/token estimates. Settle the returned reservation exactly once with nonnegative usage or `null` for unknown values. On interrupted/uncertain requests leave the reservation unresolved; never invent zero usage. |
| Tools      | Use only supplied tools and their JSON schemas; validate arguments and await execution. Carry the invocation cancellation signal. Neither repository instructions, Skills nor provider tool names authorize extra tools. No background tools after returning a final answer.                                                                                                 |
| Completion | Return final text only after verifying a complete response. Streaming `text_delta` events are provisional. Partial tool arguments and incomplete responses must never dispatch tools or establish success. No automatic retries, fallback, cache warming or extensions.                                                                                                      |
| Images     | Preserve stable reference IDs/order and exact verified image bytes. Validate persisted image content and enforce actual provider capability and aggregate bounds before dispatch. Never substitute a description for unsupported image input.                                                                                                                                |
| Failure    | Throw `AgentError` with host error codes where applicable (`AUTH`, `QUOTA`, `PROVIDER`, `REQUEST_TIMEOUT`, `INCOMPLETE_RESPONSE`, `CONTEXT_LIMIT`). Do not translate failure into a success-shaped answer. `provider_response` events carry numeric status and optional retry delay; text/tool/model-profile events are telemetry, not authorization.                        |
| Lifecycle  | `run` must drain its work before returning/throwing; `close` releases remaining adapter resources. The host blocks late tools/session/accounting callbacks, aborts the invocation signal at exit and ignores late display events. Accounting already-dispatched requests remains allowed during cancellation until invocation exit.                                          |

The host requires at least one reserved and settled request for a successful result. It rejects duplicate/unknown settlements, invalid usage, pending requests/tools, empty results, swallowed boundary failures and post-cancellation success. It cannot infer whether a trusted adapter secretly issued an extra request; adapter-specific transport tests remain mandatory.

## `messages-v1` context

The frame is a JSON object with an ordered `messages` array. Roles are `system`, `user`, `assistant`, `tool` or `toolResult`. Text may be a `content` string or `{type: "text", text}` content blocks. Images use `{type: "image", data, mimeType}` blocks with base64 data. Tool call/result IDs, error flags and provider-specific metadata must remain intact. Tool results mark failures with `isError: true` or `error: true`; all protected messages, call ordering, current results, errors and images survive host compaction verbatim. Additional fields are opaque and retained. Native formats with different roles/content must be translated at the adapter boundary; unknown roles are rejected instead of silently bypassing compaction. This shape is an application protocol, not an imported SDK type.

## Native sessions and replacement

The host treats native session files as opaque. `onSession` may register only a file in the supplied task session directory. The host stamps its adapter format alongside the file and carries it through explicit continuation. Sessions can be forked into the new task's directory, but the previous file must remain unchanged. A different format fails with `RUNTIME_SESSION` **before** reading the file or invoking the adapter. No implicit conversion or transcript deletion occurs. Restore the original adapter and explicitly resume, or use `/compact` and a new request to continue from host-owned context without reusing native session state; raw native exploration history is not automatically converted.

Existing untagged production sessions are Pi JSONL. Only the Pi adapter declares acceptance of those legacy sessions; new adapters must not claim that flag unless they actually implement that legacy reader. Pi tags newly created sessions as `pi-jsonl-v1`. Model replacement clears both native session fields, while preserving host-owned evidence and history. The metadata additions are optional for saved records and do not rewrite old session files.

## Replacement verification

`tests/runtime-contract.test.ts` exercises the host boundary and an independently implemented JSON-session fixture, including continuation, archived context, tools, unknown usage, rejection of incompatible sessions and cancellation. Existing `runtime`, `context`, `images`, `application`, `collaboration` and `model-change` tests cover the actual Pi SDK using synthetic transport. Run the relevant transport tests for each new adapter; a declaration alone is not certification.

Pi remains the configured production inference adapter. This contract does not introduce another provider backend or remove the separately pinned Pi TUI and MCP clients. Their rendering/auth/transport behavior requires their own compatibility tests when replaced. Synthetic tests do not establish real-provider image understanding, semantic procedure quality, or rendered TUI acceptance.
