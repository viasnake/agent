# Agent

## インストール

Ubuntu Server 26.04 で一般ユーザーとして実行します。

```sh
sudo apt-get update
sudo apt-get install -y git ca-certificates
git clone https://github.com/viasnake/agent.git
cd agent
bash install/install.sh
```

## 接続

別端末からは SSH で転送します。UI に認証がないため、手元の待ち受けは `127.0.0.1` に限定します。

```sh
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:8080:127.0.0.1:8080 USER@SERVER
```

CLI のログインにはサイドバーの「ターミナル」を使います。別タブで `agent-work` のホームを開き、CLI がホームに保存した認証情報はエージェントの実行でも使えます。デバイスコード方式は手元のブラウザで認証できます。タブを閉じるか「切断」を押すとシェルは終了します。同時に開ける端末は1つで、接続は最長30分です。

## Auto でモデルを選ぶ

「設定 → モデル → Auto」で、保存済みの接続を1つ選び、同じ接続の既定モデル、Cloudflare アカウント ID、Workers AI 用 API トークンを登録します。「振り分けルール」には、「短い翻訳・文章の整形」「設計の比較・難しい原因調査」など、自然文の条件と使用モデルを最大8件登録できます。初めてモデル接続を選ぶと条件の例が3件入ります。条件は編集・削除でき、使用モデルは自分で選びます。判定には Workers AI の `Clef-flash` を使います。判定に費用をかけない場合は、[Workers Free プラン](https://developers.cloudflare.com/workers-ai/platform/pricing/)のアカウントを登録してください。回答生成の費用は別です。判定の使用量は Agent の「使用量」には含まれません。

会話のモデル選択欄で `Auto` を選んだときだけ、新しい応答の開始時に短い依頼文とルールの条件を Cloudflare に送って判定します。会話履歴・メモリ・ツール出力・添付ファイルは判定には送られません。機密性のある依頼では、モデルを手動で選んでください。

明確に一致したルールのモデルを使います。該当なし、曖昧、添付付き、または判定できない場合は既定モデルを使います。既定モデルと同じAPI形式で、入力形式（画像など）とコンテキスト長を維持できない候補は、判定前に除外します。既定モデルが利用できない、または添付画像に対応していない場合は送信前に通知します。応答中は切り替えません。

## プライベートネットワークの接続先を許可する

「設定」→「ネットワーク」→「接続先の許可」で、Agent にアクセスさせたい IPv4 アドレスと TCP ポートを追加します。例えば SSH だけを許可するには、接続先の IP と「SSH（22）」を指定して保存します。未登録のプライベート宛先と管理者が保護した宛先は、引き続き拒否されます。すでに確立している通信は許可を削除しても切断されません。

「適用済み」はファイアウォールに設定が反映されたことを示します。接続試験は行わず、WARP や VPN の経路、SSH の認証設定も変更しません。独自の Agent ファイアウォールテンプレートを使用しているホストでは、この設定を利用できない場合があります。

## 長いコマンドの途中出力を確認する

エージェントが長いコマンドを開始したら、会話の「コマンドの途中出力」で直近のログを確認できます。全ログではありません。エージェントは同じコマンドの状態と終了コードを確認でき、実行中のコマンドは応答の終了・停止や時間切れで終了します。サービスを再起動してもコマンドを自動で再実行することはありません。

## ワークスペースで依頼する

「新しいスレッド」から質問や依頼を投稿します。短い質問にはその場で返信します。「保存したパッチが一覧に出ない原因を調べて、修正し、再現テストを通して」のような依頼では、主担当が作業を分担します。追加指示、担当の報告、判断が必要な質問、成果物は同じスレッドに集まります。以前の会話も掲示板から開けます。

- **ホーム**に回答待ちの質問、担当からの報告、進行中の仕事、最近の納品が集まります。質問にはその場で回答できます。
- **受信箱**（`/?view=inbox`）はスレッドごとの最新報告を表示します。未読・回答待ちで絞り込み、報告本文・成果物のプレビュー・元のスレッドを開くと、表示した投稿まで既読になります。既読はサーバーに保存されます。質問は回答するまで回答待ちに残ります。
- **掲示板**（`/?view=board`）にはスレッドが最終更新順に並びます。件名・報告・担当から検索できます。
- **成果物**（`/?view=documents`）で文書・採用済みパッチ・完了報告を横断検索できます。追加指示やアーカイブ後も過去の納品を読み返せます。本文と検証記録を開く、パッチを保存する、元のスレッドに戻る操作ができます。
- **更新履歴**には、アーカイブされていないスレッドの直近 12 投稿を表示します。
- スレッドの「担当とモデル」で、作業の分担と使用モデルを確認できます。「実行履歴」から元のメッセージとツールの実行結果を読めます。旧形式の掲示板・スレッド URL も使えます。

「設定」→「モデル」→「モデルの分担」で作業用モデルを最大 4 つとレビュー用モデルを選べます。主担当はスレッドで選んだモデルです。用途を登録すると主担当が担当を割り当てられます。用途による指定がない作業には登録順に割り当て、未設定の役割は主担当のモデルで実行します。モデルは実行開始時に固定し、時間と呼び出し回数の上限を共有します。

レビュアーは提出内容を元の依頼と実行記録に照らして確認します。同じ内容・根拠への直近の判定を再利用し、差し戻しの指摘は次の検証に引き継ぎます。採用したパッチは対応する投稿から保存できます。文案や調査結果は「本文を読む」から開きます。主担当が納品前に応答を終えた場合は、実行の上限内で続行を促します。進展がなく中断した場合は理由を表示し、スレッドから再開できます。

## 選択肢に回答する

エージェントが選択肢を出したら、ボタンを押すと選んだ内容を新しいメッセージとして送ります。選択肢に当てはまらない場合は、入力欄から自由に返信できます。回答待ちにコマンドは動き続けません。

## 使用量を確認する

各スレッドの「使用量」タブで、モデル・ツールごとの回数、エラー件数、トークンと参考費用を確認できます。全スレッドの使用量は、サイドバーの「使用量の統計」から開始日と終了日を指定すると、合計トークン・参考費用・日別トークンを確認できます。モデル・ツール別の内訳や日別の呼び出し件数は「詳しい内訳」を開くと表示されます。日付の区切りはブラウザのタイムゾーンです。

## Git リポジトリを使う

「設定」→「Git」で、作業ユーザーのコミット作成者名（`user.name`）とメールアドレス（`user.email`）を変更できます。空欄にして保存すると、該当するグローバル設定を削除します。リポジトリ個別の設定は引き続き優先されます。

エージェントはスレッド内に clone を作ります。最新のコードが必要な作業では対象ブランチを作業直前に `fetch` し、取得したコミットを使います。

共有ミラーを使う場合は、管理者がリポジトリごとに設定します。ミラーはスレッドから読み取り専用で、メモや成果物を置く `work/shared` は引き続き書き込めます。下の例では既定のデータパス `/srv/agent-data` を使います。変更している場合はコマンドとサービス定義のパスを合わせてください。

```sh
# 更新専用の一般ユーザーを初回だけ作成する
sudo useradd --system --create-home --home-dir /var/lib/agent-git --shell /usr/sbin/nologin agent-git
sudo chmod 0700 /var/lib/agent-git
sudo install -d -o root -g agent-work -m 0750 /srv/agent-data/git-mirrors

# リポジトリごとに名前と URL を設定する
name=owner--repo
url=https://github.com/OWNER/REPO.git
mirror="/srv/agent-data/git-mirrors/$name.git"
sudo install -d -o agent-git -g agent-work -m 2750 "$mirror"
sudo -u agent-git -g agent-work -- /bin/sh -c \
  'umask 027; exec /usr/bin/git clone --bare --no-tags --template= -- "$1" "$2"' sh "$url" "$mirror"

sudo install -m 0644 examples/agent-git-refresh@.service examples/agent-git-refresh@.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now "agent-git-refresh@$name.timer"
```

更新は毎時実行されます。非公開リポジトリでは `agent-git` に専用の読み取り用 SSH 鍵と検証済みの `known_hosts` を設定し、認証情報を含まない SSH URL を指定します。スレッドでの `fetch` には Agent の作業用認証設定を使います。従来の共有チェックアウトを移行するには、必要なリモートからミラーを新規作成してください。

## コードと文書を並列で変更する

会話で、たとえば「このリポジトリの CSV 出力を修正し、README の利用例も更新して。コードと文書を並列で作業して、テストした差分を渡して」と依頼します。Agent がスレッド内の Git clone から基点を選び、担当ファイルごとに指示を出します。各担当には、基点時点の担当ファイルと指示を渡します。必要に応じてテストや型定義などの参照ファイルを担当ごとに 2 件まで添えられます。独立して編集できる UTF-8 ファイルを 2～6 件指定でき、同時に 2 件ずつ進みます。

会話の「並列作業」には担当ごとの試行回数と結果が表示されます。「検証内容」で基点、検証コマンド、対象の Git ツリー、出力を確認できます。検証に成功すると「検証済みの差分を保存」からパッチを取得できます。表示された基点の checkout に `git apply --index <パッチのパス>` で適用できます。

「差分を確認」で変更行と検証ログを確認できます。修正した場合も以前の差分を開けます。「作業フォルダに保存」は検証済みの差分をスレッド内の `outputs/` に置きます。続けて「作業ブランチに適用して PR にして」と依頼すると、Agent はこのパッチを使って通常の Git 操作を続けられます。GitHub への書き込みには作業環境で利用できる認証が必要です。

検証が失敗した場合は、会話で「コード側だけ修正して」と指示できます。会話の「担当に修正を依頼」から対象ファイルと修正内容を直接指定することもできます。ほかの担当が完了した変更は再利用されます。「一時停止」は実行中の工程が終わったところで次の工程を待たせます。「再開」は未完了の担当、または固定済みの差分の検証から続けます。検証中にサービスが停止した場合は、外部への影響を確認してから再開してください。会話の応答を止めても並列作業は続きます。作業そのものを終了するには「作業を取り消す」を押します。

## 送信済みのメッセージを編集する

送信済みの自分のメッセージで「編集」を押し、その場で本文を書き換えて「送信」を押します。元の会話は残り、編集後のメッセージには新しい分岐で回答します。元の画像は引き継ぎますが、スレッドの作業ファイルはコピーしません。

## スキルを使う・管理する

Agent は普段の会話や作業で再利用できる手順を確かめたときに、スキルを作成したり、既存のスキルの本文を直したりします。「この手順をスキルにまとめて」と普通の言葉で頼むこともできます。反映後は会話に変更内容が表示されます。

設定の「Skills」から、人がスキルの本文を編集・削除できます。自動メンテナンスに設定やコマンドは不要です。更新案を作った後で対象のスキルが変更されていた場合、古い案で上書きしません。

## コードの変更を確認する

スレッドの「変更」タブで、変更ファイルを選ぶと、追加行・削除行を行番号付きで確認できます。スマートフォンでは「変更ファイルに戻る」で一覧へ戻ります。複数のクローンがある場合は、先にリポジトリを選んでください。 添付・生成ファイルは「ファイル」タブからダウンロードできます。

- **未コミットの変更**は、現在の `HEAD` との差分と、`.gitignore` や `.git/info/exclude` で無視されていない未追跡ファイルを表示します。今回の応答より前からある変更も含まれます。
- **コミット済みの変更**は、初期状態では現在のコミットの直前を起点にします。コミット名と日付が並ぶ「比較の起点」で、別のコミットを選ぶこともできます。選んだ時点の状態と現在のコミットを比較し、未コミットの変更は含みません。候補は現在のブランチの主な履歴から直近50件までです。

対象はスレッド内の通常の Git クローンです。共有リポジトリ、リンクされたワークツリー、サブモジュールは対象外です。差分の表示は読み取り専用で、バイナリや表示上限を超える差分は本文を表示しません。対象のスレッドが実行中の場合やターミナルが開いている場合は、実行を終えるかターミナルを閉じてから更新してください。

## 更新

### Agent 本体だけを更新する

ホット更新に対応した版がすでに動いている場合は、管理者用のシェルで次を実行します。Agent のターミナルから実行する操作ではありません。

```sh
git pull --ff-only
bash install/install.sh --hot-update
```

新版のビルド中は通常どおり使えます。準備ができると新しい実行の受付を一時停止し、進行中の応答やコマンドが終わり、開いているターミナルが閉じるのを最長60秒待ちます。間に合わなければ旧版のまま受付を再開します。切り替え時だけブラウザーの接続が切れ、開いている会話は自動で再接続します。切断時に届いたか分からない送信は自動で再送しません。途中の OAuth 認証はやり直してください。

更新中に別のサービス起動・停止操作は行わないでください。切り替え後の起動を確認できなかった場合は、`systemctl status agent.service` と `journalctl -u agent.service` で状態を確認してください。旧版のアプリは表示された `/opt/agent.previous-*` に残ります。新版が処理を受け付けていた可能性があるため、自動で旧版には戻しません。

### サービスを停止して更新する

ホット更新の初回導入、Node.js・Python・サービス設定などインストール関連の変更、データ互換性が変わる更新には従来の手順を使います。

```sh
git pull --ff-only
sudo systemctl stop agent.service
# 1.5.x から更新する場合は、SQLite のバックアップ機能でデータ領域の control/conversations-v1.sqlite を保存
bash install/install.sh --update
```

Pi Durable 1.6.0 から 1.5.x に戻す場合は、更新前の会話データベースを復元してください。

## テスト

```sh
export PATH="/opt/agent-node/bin:/opt/agent-python/bin:$PATH"
npm ci --ignore-scripts --no-audit --no-fund
npx playwright install --with-deps chromium
npm run verify
```

実際に設定したモデルでも並列作業を確認できます。テスト用の新しい会話に送る依頼を用意し、作業対象と合格条件を確認してから実行します。たとえば、依頼には「スレッド内に小さな Git リポジトリを作り、コードと README を並列で更新する。境界値のテストを実行し、検証したパッチを残す」と記載します。サービスを起動した状態で実行してください。

```sh
AGENT_LIVE_TEST=1 AGENT_LIVE_PROMPT_FILE=./reviewed-prompt.txt npm run test:live -- --parallel-work
```

検証に通った Git ツリーと SHA-256 を出力します。ダウンロードしたパッチと作業フォルダに保存したパッチの中身も照合します。

チーム作業の実機 QA には、`--parallel-work` の代わりに `--project` を指定します。依頼文の例は「Alpha は受け入れテスト 12 件に合格。Beta はロールバック試験に失敗。両製品の金曜リリース可否をまとめて」です。テストは通常の API から新しいスレッドを作り、2 担当以上の報告、完了報告の照合、ダッシュボードへの反映を確認します。出力されたスレッド ID で報告内容も確認できます。
